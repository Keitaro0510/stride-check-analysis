# ステップ1：データの取得と整理

実行：`bash run.sh`（`prepare_npj.py` → `prepare_loh.py` → `prepare_fukuchi.py` → `denormalize_npj.py` の順に実行する）
入力はすべて `BioHackathon2026/analysis_data/`（最終決定したデータ）。出力はすべて `outputs/`。入力データは変更しない。

## 前提と判断

### npj 2026
- 人のIDは、遺伝子型＋性別＋身長の組み合わせが変わる行を切れ目として付けた。142名で論文と一致
- 走り方（床反力）は1人1値。参加時に1回測った値が全部の週に入っている
- `sex = 0` が78名で、表1の男性78名と一致するので、0 = 男性とした
- **元の単位への変換**（`outputs/npj_denorm_check.txt`）
  - 表1から戻せた：体重、BMI、過去1年のケガの日数、衝撃のピーク（12 km/h）、Duty factor（12 km/h）
  - 年齢は範囲の下限が約0歳になり不自然なので、使わない
  - 接地時間・滞空時間・ピッチ（10・12 km/h）と Duty factor（10 km/h）は、物理的な関係（ピッチ×1歩の時間＝60、Duty factor＝接地÷1歩）と、Fukuchi の平均（速度で内挿）を基準にして戻した
    - 基準に使っていない接地時間と滞空時間の平均・SD が Fukuchi とほぼ一致
    - 10 km/h と 12 km/h を別々に戻したのに、ほぼ全員で 12 km/h のほうがピッチが高い（平均 +5.3 歩/分、相関 0.96）
    - **ただし絶対値は Fukuchi の集団に合わせたもの**で、npj の本当の平均とずれている可能性がある
  - 戻せない（パーセンタイルで扱う）：左右差、負荷率、10 km/h の衝撃のピーク、左右で接地の仕方が違うか

### Loh 2025
- ラベルは `Injured`（人ごと）だけを使う。`Injury` 列は意味が不明なので使わない
- **ケガをした26名は、1名を除いて片側の脚だけに角度がある**（`Injury` 列が空欄の人は左、1 の人は右）。ケガをした側の脚だけを載せている可能性があるが、未確認。ケガをしなかった55名は両脚ある
  - 1人1行の表の角度は「角度のある側の平均」。左右差はタイプ分けに使わない
- 足首の背屈は、左に約40°の値（52脚）が混ざっているので使わない
- ピッチが100未満の2名（ID 53, 55）は入力ミスとして欠損にした

### Loh & Kong 2026
- 受傷した脚ごとに、ケガの種類と部位（腰・股関節／太もも・膝／下腿・足首・足）を付けた
- 受傷者の角度のシートにあって参加者一覧にないIDが1脚ある（種類は空欄）

### Fukuchi 2017
- figshare の最新版（ランナー39名。論文の時点は28名）。CC BY 4.0
- 床反力は 300 Hz、鉛直成分 `Fy` が 50 N を超えている間を接地とした
- 接地時間の左右差は、1歩おきの差として計算（床反力だけではどちらが左右か分からない）
- C3D とマーカーの生データもダウンロードしているが、ここでは使っていない（ezc3d がこの環境に入らないため、必要になればテキスト版のマーカーを使う）
