# ステップ3：① 走り方のタイプ分け

## 3-1 リズムのタイプ（npj 2026）✅

実行：`bash run.sh`（3-1〜3-3、約11分）／`bash run.sh rhythm`（3-1 だけ、約2分）／`bash run.sh form`（3-2 だけ、約8分）。前提：`../step1_data/run.sh` を実行済み
結果のまとめ：[`outputs/rhythm_report.md`](outputs/rhythm_report.md)

### 目的
参加時に測ったリズム（ピッチ、Duty factor など）でランナーをタイプに分け、各タイプのランナーがその後どれくらいケガをしたかを出す。新しいランナーを判定するための値を書き出す。

### 入力
`../step1_data/outputs/` の `npj_person.csv`、`npj_person_raw.csv`、`npj_weekly.parquet`

### スクリプト
| ファイル | 中身 |
|---|---|
| `common.py` | パス、乱数の種、項目の組み合わせ、採用の基準 |
| `01_features.py` | 1人1行の特徴量と結果の表。走り方の値を埋めたと思われる人の検出 |
| `02_cluster.py` | 分け方の比較（k-means／混合ガウスモデル／ルール × タイプの数 × 組み合わせ）と、ケガの結果を見る前に決めた基準での採用 |
| `03_outcomes.py` | タイプごとのケガの多さ（Kaplan-Meier、Cox、負の二項回帰）、調整、連続値での分析、感度分析、検出できる差、図 |
| `04_export.py` | 判定用の `types_rhythm.json`、Fukuchi のランナーでの確認、基準の不確かさの影響 |
| `05_report.py` | `rhythm_report.md` を成果物の数値から作る |

### 主な成果物（`outputs/`）
| ファイル | 中身 |
|---|---|
| `rhythm_report.md` | 結果のまとめ |
| `types_rhythm.json` | 判定用（組み合わせ A・B・C） |
| `rhythm_cluster_selection.csv` | すべての分け方の評価指標と採用 |
| `rhythm_outcomes.csv`・`rhythm_tests.csv` | タイプごとのケガの割合・率・ハザード比、検定 |
| `rhythm_continuous.csv`・`rhythm_sensitivity.csv`・`rhythm_power.csv` | 連続値、感度分析、検出できる差 |
| `rhythm_km.png`・`rhythm_forest.png`・`rhythm_map.png` | 図 |
| `run_log.txt` | 実行時の出力 |

### 判断
- 結果（ケガ）：初めてケガをするまでの週（`time`、ケガがなければ追跡した週数で打ち切り）。主な指標は52週以内のケガの割合
- ID 70・71 はタイミングの全項目が完全に同じで、女性の中央値とほぼ一致したので、走り方の値を埋めた人とみなして除いた（論文では1名。含めた場合は感度分析）
- 使う速度は時速10km。ピッチ・接地・滞空・Duty factor は物理的な関係で2項目に集約できるので、ピッチと Duty factor を代表にした
- 採用の基準は結果を見る前に決め、`02_cluster.py` の冒頭に書いた
- **画面に使う組み合わせは B**（9/17 ユーザーの判断で A から変更。`common.py` の `SELECTED_VARIANT`）。感度分析・図・判定の確認は B を基準に出す

### 結果の要点
- **どの分け方でも、タイプ間でケガの多さに統計的な差はなかった**
  - 組み合わせB（3タイプ、主に接地の仕方で分かれる）：52週以内のケガの割合 R1（左右で接地が違う、20名）67%、R2（踵接地が多い、65名）88%、R3（踵接地が少ない、55名）85%。log-rank p=0.20
  - 組み合わせA（2タイプ）：両タイプとも約83%、ハザード比 0.89［0.61〜1.31］
- 組み合わせBで判定するには、動画から接地の仕方と左右差を測る必要がある（ステップ2）
- 連続値でも、調整しても、感度分析でも同じ。この人数で検出できるのはハザード比約1.7以上の差

## 3-2 フォームのタイプ（Loh 2025）✅

結果のまとめ：[`outputs/form_report.md`](outputs/form_report.md)

### 目的
参加時に2D動画で測ったフォーム（骨盤の傾き、股関節の内転、膝の屈曲、膝の外反）でタイプに分け、各タイプのランナーが12か月でどれくらいケガをしたかを出す。動画で測った値を脚ごとに当てはめるための値を書き出す。

### 入力
`../step1_data/outputs/` の `loh2025_limbs.csv`、`lk2026_limbs.csv`（角度の尺度の確認用）

### スクリプト
| ファイル | 中身 |
|---|---|
| `11_form_features.py` | 脚ごとの特徴量と重み、速度補正、角度の尺度と相関（符号の向き）の確認 |
| `12_form_cluster.py` | 分け方の比較（重み付き k-means／混合ガウスモデル／ルール × タイプの数 × 組み合わせ）と、結果を見る前に決めた基準での採用 |
| `13_form_outcomes.py` | タイプごとのケガの割合（重み付き、人単位ブートストラップ）、オッズ比と調整、並べ替え検定、連続値、感度分析、検出できる差、図 |
| `14_form_export.py` | 判定用の `types_form.json` |
| `15_form_report.py` | `form_report.md` を成果物の数値から作る |

### 判断（9/17 ユーザー了承）
- ケガをした人は1名を除き片脚だけに角度があるので、**脚を単位**にし、重み = 1 ÷ その人の脚の数。信頼区間と安定性は人単位のブートストラップ。画面では**左右の脚それぞれ**のタイプを出す
- 1タイプの最小は重み付き**15人分**
- 調整は**性別・年齢・週の走行距離**（Loh 2025 にケガ歴はない）
- 画面に使う組み合わせは、ステップ2の結果が出るまで A（`common.py` の `FORM_SELECTED_VARIANT`）
- 画面ではリズム（B、npj 2026）とフォーム（Loh 2025）を別々に表示し、組み合わせのケガの割合は出さない

### 分析中に分かったこと
- **Loh & Kong 2026 の健常群だけ、股関節の内転と膝の外反の相関が負**（他のデータは正）。健常群のシートは膝の外反の符号の向きが逆の可能性が高い
- 骨盤の傾きと股関節の内転の値は、すべてのデータで負の相関。**股関節の内転の値は「大きいほど内転が小さい」、膝の外反は「正のとき膝が外に開く」と解釈**してタイプに名前を付けた（未確定、ステップ2で確認）

### 結果の要点
- **タイプ間でケガの割合に統計的な差はなかった**（組み合わせA：F1 股関節の内転が小さい・膝が外に開く 28%、F2 股関節の内転が大きい・膝が内に入る 36%、並べ替え検定 p=0.44）
- 連続値では、膝の屈曲が深いほどケガが少ない傾向（1SDあたりのオッズ比 0.55、p=0.02）。4角度を試した中の1つなので探索的な傾向
- 股関節の内転の値は、ケガの後（Loh & Kong 2026 受傷群）では健常群と約0.9SD違うが、ケガの前（Loh 2025）ではほぼ差がない。ケガの後の違いは、かばった結果の可能性

## 3-3 見やすいタイプの分け方の探索 ✅（9/17 リズム・フォームとも案1を採用）

結果のまとめ：[`outputs/explore_report.md`](outputs/explore_report.md)

### 目的
ステップ5-2の結果、予測にタイプを使わないことになったので、タイプを「説明しやすく、分布図の上できれいに分かれて見える」基準で選び直す。

### スクリプト
| ファイル | 中身 |
|---|---|
| `31_explore_types.py` | 候補の作成と評価。区切り（2区分・3区分）、2軸だけの k-means（k=2〜8）、混合ガウスモデル（リズムのみ）。安定性（人単位ブートストラップ200回）、最小タイプの割合、偏り、シルエット係数 |
| `32_explore_gallery.py` | 全候補と絞り込んだ候補の、境界つき分布図。`explore_report.md` |
| `33_export_display_types.py` | 採用した分け方の判定用ファイル `types_display.json`（閾値、閾値の95%信頼区間、速度の補正、タイプごとの割合と平均、分布） |

### 判断
- 分布図の2軸とタイプを作る項目を一致させる（これまでの分け方は、作った項目と図の軸がずれていて、色が混ざって見えた）
- ケガとの関係は評価に使わない
- フォームは「脚のアライメント」（股関節の内転の値と膝の外反の標準化の平均）を新しい軸として試した
- 絞り込みは、2軸の区切りの上位2つ、k-means の上位1つ、1軸の区切りの上位1つ（最初は grid 優先で上位3つにしたが、フォームで1軸ばかり残ったので変更）

### 採用した分け方（画面に使う）
| | 分け方 | タイプ |
|---|---|---|
| リズム | ピッチ（中央値 162.6 歩/分）× 接地の仕方（踵／踵以外） | ローピッチ×踵以外 26%、ローピッチ×踵 24%、ハイピッチ×踵以外 28%、ハイピッチ×踵 22%（安定性 平均0.93） |
| フォーム | 骨盤の傾き（中央値 5.5°）× 膝の屈曲（中央値 40.5°）、脚ごと | 安定×浅い 22%、安定×深い 28%、落ちる×浅い 28%、落ちる×深い 22%（安定性 平均0.87） |

- 閾値の95%信頼区間（人単位ブートストラップ2000回）に入る値は、画面で「どちらのタイプにも近い」と表示する。該当するのはリズム16%、フォーム35%（どちらかの軸）
- これまでの `types_rhythm.json`（組み合わせB）と `types_form.json`（組み合わせA）は、比較と記録のために残すが、画面には `types_display.json` を使う
